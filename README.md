# Word 一键水印工具（WriteMark）

一个用 Python + PySide6 编写的 Windows 小工具：对 Word 文档 **一键插入/清除水印**，
支持 **文本水印与图像水印同时叠加**、**中文字体/西文字体分别设置**、**上下左右偏移**，
并带 **后台守护（水印被删自动补回）** 与 **无需打开 Word 的实时预览**。可打包为独立 `.exe`，双击即用。

## 功能

- **文本 + 图像水印可同时叠加**
  - 文本水印：自定义文字、**中文字体 / 西文字体分别指定**、字号、颜色、旋转角度、透明度、缩放。
  - 图像水印：自定义图片、旋转角度、透明度、缩放。
  - 两类水印各有 **独立的一套参数**（角度/透明度/缩放/偏移互不干扰）。
- **Word 式“中文字体 / 西文字体”分别设置**
  - 汉字、中文标点走中文字体；字母、数字、半角符号走西文字体。
  - 例：`机密 CONFIDENTIAL` 可设为“机密=仿宋，CONFIDENTIAL=Times New Roman”，与 Word 字体对话框语义一致。
  - 两个字体框都 **可直接键入筛选**（输入 `t` 出 Times New Roman，输入 `仿` 出仿宋）。
  - 导入 Word 后可授权读取本机可用字体（Word 在场时约 1400 种）扩充下拉框；仅读取字体名，不访问文档内容。
- **上下左右偏移**：文本与图像水印都能按页宽/页高百分比做水平/垂直偏移。
- **一键清除**：既能清掉本工具加的水印，也能清掉 **Word 原生水印**（衬于文字下方的图形）。
- **不破坏原文件**：默认 **另存为** `桌面/<原名>WaterMark.docx`，原文件保持不变，输出路径可自定。
- **后台守护（防篡改）**：按设定间隔检查，水印被删则自动补回；**支持按份数校验**（水印被删掉一部分也整体补齐）；
  可 **最小化到系统托盘常驻**——关掉主窗口后守护继续在后台运行。
  **点关闭按钮时总会弹窗让你选“最小化到后台 / 退出程序 / 取消”**，不会再出现“以为只是关窗、结果整个程序没了”。
- **防去除加固（可选）**：见下方 [专节](#防去除加固能挡住什么挡不住什么)。
  - **平铺满页水印**：从“单个居中”改为整页多行多列平铺，抹除难度陡增。
  - **多份冗余嵌入**：页眉 + 页脚都写入，且图形显示名不含 `watermark` 字样。
- **实时预览**：改任意参数约 0.2 秒后自动刷新 A4 示意预览，可导出 PNG。

## 环境要求

- **Windows** 操作系统。
- **兼容 WPS Office 与 Microsoft Word**（水印为标准 OOXML “页眉中衬于文字下方的图形”）。
- **`.docx`**：无需安装 Word/WPS，纯 Python 处理，便携性最好。
- **`.doc`（Word 97-2003）**：**必须本机安装 Microsoft Word**（走 Word 自动化，纯 Python 无法读写 `.doc`）。

## ⚠ 操作前必读：先关闭 WPS/Word

- 插入/清除前请 **完全退出 WPS/Word**；文件被占用时工具会明确提示而不是默默失败。
- **WPS 关闭窗口后进程可能仍驻留后台并锁定文件**：可在任务管理器结束 `wps.exe` 后重试。
- 开启“守护”时，文件被占用期间守护会自动暂停读写，待空闲后自动恢复，不与编辑器争抢文件。

## 使用

运行 `WordWatermark.exe`（或 `python main.py`）：

1. 点“浏览...”选择 Word 文件（`.docx` / `.doc`），程序自动给出默认输出路径（桌面/<原名>WaterMark.docx）。
2. 需要改名/改位置就点“输出”右侧的“浏览...”（**不会覆盖原文件**；若输出设为与源文件相同，会自动加 `_水印` 后缀保护原文件）。
3. 勾选“启用文本水印”/“启用图像水印”（可同时启用），分别设置各自参数。
4. 文本水印里分别选 **中文字体** 与 **西文字体**，调字号、颜色；用“水平/垂直偏移”调整位置。
5. **实时预览**：改任意参数约 0.2 秒后预览区自动刷新，无需点按钮。
6. 点 **一键插入水印** 或 **一键清除水印**（在新文件上操作，原文件不变）。
7. 需防篡改就勾选“启用守护”并设置检查间隔（默认 1 秒，最小 0.2 秒），取消勾选即停止。

> **插入后看不到水印？** 依次检查：
> 1. Word 必须处于 **页面视图 / 打印布局**（“草稿”或“Web 版式”不显示页眉水印），WPS 对应 **页面布局** 视图。
> 2. 文件是否正被 Word/WPS 打开（会被锁定导致保存失败，先关闭再操作）。
> 3. 处理 `.doc` 时本机必须装有 Word（缺 Word 会弹窗报错）。

## 关闭窗口时会发生什么

点标题栏的 ×（或 Alt+F4）**总会先弹出选择**（不论有没有开启后台守护）：

| 选项 | 行为 |
| --- | --- |
| **最小化到后台** | 窗口隐藏到系统托盘，进程继续运行；若守护开着，水印照常补齐。单击/双击托盘图标可唤出窗口 |
| **退出程序** | 停止守护并完全退出进程 |
| **取消** | 什么都不做，回到界面 |

托盘不可用时（少数精简版系统）会明确告诉你原因；此时仍可选"最小化到后台"，
但因为没有托盘图标，重新打开界面需要再次运行程序。托盘初始化失败会自动重试一次，
并在日志区打印失败原因，便于定位。

## 曾经被误当成"退出卡顿"的两件事：幽灵 Word 与 Office 联网等待

### 1) 幽灵 Word（已在 v1.1.3 从源头消除）

**旧症状**：任务管理器里一直有个看不见的 WINWORD.EXE。

**旧原因**：为了拿到中文本地化的字体名（要"宋体"而不是 "SimSun"），工具会通过 Word COM
临时启动一个不可见的 Word 去取字体列表。早先版本只调 `word.Quit()` 就完事，但 Word 在
有外部 COM 引用、或自身还没启动完时**会忽略这个 Quit**，于是留下一个看不见的 Word 进程。

**v1.1.2 的收尾加固**（`watermark_tool/com_cleanup.py`）：调用前记录现有 WINWORD 进程 →
读完后 `Quit` → 释放引用并 `gc` → 给它几秒自行退出 → 仍不退才**只强制结束我们自己新起的
那个 pid**（绝不碰用户自己开着的 Word）。

**v1.1.3 的做法更好：根本不再启动 Word。** 中文名改由一张本地化映射表给出
（`word_fonts._CN_NAME_MAP`，且只收录本机真实存在、能解析到字体文件的名字），
字体列表直接从 Windows 字体注册表读取。效果：

| | v1.1.2（走 Word COM） | v1.1.3（注册表） |
| --- | --- | --- |
| 获取字体耗时 | 5.5 秒（会临时起一个 Word） | **0.006 秒，零副作用** |
| 字体条数 | 1414（含 `@宋体` 等竖排变体） | 378（已过滤无用变体） |
| 中文字体名 | 有 | 有（宋体/黑体/微软雅黑/仿宋/楷体/等线…共 27 个） |

回归测试（需本机装有 Word）：

```bat
python test_font_com_cleanup.py   :: 两条路径都要求 WINWORD 零残留
python test_no_word_process.py    :: 全流程持续监控，一次 WINWORD 都不许出现
python test_exe_no_word.py        :: 交付版 exe 从启动到退出同样不许出现
```

> ⚠ 写这类测试有个陷阱：**只在调用前后各查一次是不够的。** 如果进程被拉起后很快又退出，
> 事后检查照样"看起来很干净"。必须开一条监控线程持续采样，并且用"人为起一个 Word"做自检，
> 确认监控真的抓得住 —— 否则那条"未见 Word"可能只是空结论。

### 2) Office 关闭时等待微软云端（与本机有关，与本工具无关）

如果你关 Word / PowerPoint 都要等十几二十秒，那既 exudates 不是本工具造成的。实测：

```bat
python test_office_exit_lag.py        :: Word / Excel / PowerPoint 关闭耗时对照
python test_com_side_effect.py        :: 即便真的用过 COM，之后关 Word 会不会更慢
python test_word_close_profile.py     :: 采样关闭那 20 秒里 Word 到底在等什么
```

在本机（Office 365、已登录 Microsoft 账户）的实测数据：

| 现象 | 结果 |
| --- | --- |
| 点×到进程退出 | Word 18.6s，**PowerPoint 18.6s**（本工具从不调用它），Excel 3.2s |
| 其中干等的时间 | 前 16 秒 **CPU 0ms、磁盘 IO 0**，同时挂着 8 条到微软云 443 的 ESTABLISHED 连接 |
| 先跑一次 COM 读字体，再关 Word | 18.58s → 18.50s，**差值 -0.09s**（噪声级） |

结论：**Word / PowerPoint 在退出时要同步等待微软云端服务的会话释放**，这段时间它什么都不做。
这与本工具无关（PowerPoint 从未被碰过也一样慢），要解决得从 Office 侧入手，例如：
在「文件 → 账户」里注销 Microsoft 账户、或在「文件 → 选项 → 信任中心 → 隐私选项」里关掉
联网的连接体验；网络策略严格的环境（代理/防火墙拦微软端点）也会显著加重。

## 为什么以前“关闭后要卡十几秒”——根因不在代码里

这是一个被反复报告、也确实一直没修好的问题。**源码版运行和关闭的实测耗时是：窗口关闭 0.1 秒、进程退出 0.2 秒**——
Python 代码本身早就没有任何卡顿了。真正的原因在打包方式：

- PyInstaller 的 **onefile（单文件）** 每次运行都会把整个运行时解包到 `%TEMP%\_MEIxxxxxx`
  （本项目约 **223 个文件 / 131 MB**）。
- **关闭窗口之后**，bootloader 必须把这一整个目录删干净，进程才真正退出。
- 本机实测：窗口 0.1 秒消失，但进程要 **8.7 秒**才结束（更早未裁剪版本是 **11.6 秒**）；
  叠加杀毒软件对每个 DLL 的实时扫描，到 20~30 秒很正常。

也就是说，**只要还用 onefile 打包，代码改到极致也消不掉这段等待**。所以 v1.1.1 换了交付形态：

| | 旧的做法（onefile） | 现在的做法 |
| --- | --- | --- |
| 每次运行 | 解包 131 MB 到临时目录 | 运行体常驻 `%LOCALAPPDATA%\WriteMark\runtime\<版本>`，只在**首次使用时**解压一次 |
| 关闭时 | 删除整个临时目录 → 卡 8.7s~30s | 没有任何清理动作 → **0.1 秒以内**退出 |
| 启动速度 | 每次都要现场解包 | 首次约 2.9 秒，之后约 1.5 秒 |

对使用者的感受没有任何变化：**依然只有一个 `WordWatermark.exe`，双击即用**。
它是一个 7 MB 的启动器，运行体压缩包以自解压方式追加在它尾部，首次运行时展开到本地、长期复用。
代价是本地会常驻约 **135 MB** 的运行体目录（换版本时旧目录会被自动清掉）。

想自己验证的话：

```bat
python test_exit_timing.py exe       :: 对比旧 onefile 版“关闭→进程结束”的秒数
python test_launcher.py              :: 新 exe 端到端：首次/二次启动耗时 + 关闭退出耗时
```

## 防去除加固：能挡住什么、挡不住什么

先说结论，避免期待落空：**没有任何方案能保证水印"绝对删不掉"**。本工具做的是把"删水印"的成本抬高，并挡住最常见的几条路径。

| 加固项 | 挡住谁 | 原理 |
| --- | --- | --- |
| **平铺满页水印** | **PS 内容识别填充 / AI 修图去水印** | 稀疏的单个居中水印，AI 很容易抹掉且不留痕迹；覆盖整页的密集纹理要想去掉，等于把整页重画 |
| **多份冗余嵌入**（页眉+页脚） | 在 Word/WPS 里点"删除水印"、或只清页眉的脚本 | 页眉那份被删了，页脚那份还在；每个 part 还有 N 份 |
| **伪装显示名**（不含 `watermark` 字样） | 按名称/结构匹配的去水印宏与脚本 | 它们按名字找水印图形，认不出我们的图形 |
| **守护按份数校验** | 手动删掉一部分的人 | 份数一少就整体补齐 |

**必须说清的三个边界：**

1. **守护只对"你自己机器上的那个文件"有效。** 它是个自愈监控进程，不是加密。文件一旦发给别人，别人手里那份跟你机器上的守护没有任何关系。
2. **PS 打不开 `.docx`。** 别人用 PS/AI 去水印，路径必然是 `docx → 导出 PDF/图片 → 修图 → 再导出`。到修图那一步，水印已经是**像素**，docx 里的任何结构（名字、份数、保护）都已不存在——**此时只有"平铺"这一项还起作用**，因为它是唯一让水印在像素层面难以清除的手段。
3. **`.docx` 本质是个 zip。** 任何拿到文件的人都能解压、改 XML、重新打包。因此任何"docx 层面的保护"都是提高门槛，不是绝对防线。

## 如何验证“后台守护”

守护监控的是**输出文件**：只要它的水印没了、份数少了、或文件被整个删除，就自动从**源文件**重新生成补回。

两点注意：
- 守护在**工具运行时**工作。关掉主窗口时会**最小化到系统托盘**（右键托盘图标可显示窗口 / 停止守护 / 退出程序），守护继续在后台跑；只有从托盘选"退出程序"或取消勾选"启用守护"才会真正停止。
- 输出文件正被 Word/WPS 打开时会自动暂停（日志会提示"文件被占用，守护暂停读写"）。

### 手工验证（最直观，1 分钟）

1. 准备一个测试文档 `test.docx`（随便写几行字）。
2. 工具里选择它 → 输出设为 `桌面\test_守护.docx` → 勾选“启用文本水印”，文字填“机密 TEST”。
3. 点 **一键插入水印**，打开输出文件确认已有水印。
4. 勾选 **启用守护**，检查间隔设为 0.5 秒，然后**保持工具窗口开着**。
5. 任选一种方式把水印弄掉：
   - **方式 A（模拟被人清除）**：在 Word 里打开输出文件 → `设计/页面背景 → 水印 → 删除水印` → 保存 → **关闭 Word**（关掉后文件才不被锁，守护才会动）。
   - **方式 B（手动删除）**：双击页眉进入编辑 → 选中水印图形 → Delete → 保存并关闭 Word。
   - **方式 C（删文件）**：直接把 `test_守护.docx` 删掉。
   - **方式 D（只删一部分，验证按份数校验）**：勾选"平铺满页 + 多份冗余嵌入"插入后再开守护（此时会写入很多份），然后在 Word 里只删掉其中几个图形并保存关闭。
6. 等待约 1 秒（不超过一个检查周期），重新打开输出文件：水印应已自动回来（方式 C 会连文件一起重建）。
7. 工具下方日志区会打印下列之一：
   - `⚠ 检测到水印被移除，已自动从原文件补回。`
   - `⚠ 检测到水印被部分移除（3/16 份），已自动补齐。`（方式 D）
   - `⚠ 输出文件已被删除，已自动从原文件重新生成并加水印。`（方式 C）
   - `· 水印在位。`（一切正常，仅状态行显示）
8. 取消勾选"启用守护"即停止；关掉主窗口则最小化到托盘继续运行。

## 从源码运行 / 打包

依赖：`python-docx`、`Pillow`、`pywin32`、`PySide6`、`PyInstaller`。

```bat
python main.py                                    :: 直接运行源码
build.bat                                         :: 一步构建出 dist/WordWatermark.exe
```

`build.bat` 内部会做三件事（细节见 `build_launcher.py`）：

1. 把上一次的 `dist/WriteMarkApp` **改名挪走**，再让 PyInstaller 从零构建运行体
   —— 这一步不能省：PyInstaller 重建时先要删掉旧目录，一旦这个删除被安全策略拦下，
   **它不会报错，产物却会静默停留在旧版本**（本项目真实踩过这个坑：测试全绿，
   跑的还是旧程序）；
2. 校验新运行体确实比源码新，不新就直接报错退出；
3. 压缩成 `payload/app_payload.zip` 并追加到启动器 exe 尾部。

只重建运行体 / 只重打包可以用：

```bat
python -m PyInstaller WordWatermark_app.spec --noconfirm   :: 运行体 dist/WriteMarkApp/
python build_launcher.py --skip-app                        :: 跳过第 1 步，仅重做 payload 与 exe
```

产物在 `dist/WordWatermark.exe`（单个文件，可拷贝到任意 Windows 机器运行；处理 `.doc` 的机器仍需安装 Word）。
首次运行时会在 `%LOCALAPPDATA%\WriteMark\runtime\<版本>` 展开运行体并显示一次进度提示。

仓库内 `test_*.py` 为自动化测试，可直接逐个运行：

```bat
python test_close_confirm.py   :: 关闭按钮三种选择（最小化 / 退出 / 取消），开不开守护都验证
python test_close.py           :: 关闭流程不阻塞（守护、进行中的插入任务）
python test_font_com_cleanup.py:: 读字体不留“幽灵 Word”（需本机装有 Word）
python test_no_word_process.py  :: 全流程持续监控：一次 WINWORD 都不许出现（含监控自检）
python test_exe_no_word.py      :: 交付版 exe 启动到退出同样不许出现 WINWORD
python test_launcher.py        :: 交付 exe 端到端，含“关闭→进程结束”耗时
python test_exe_verify.py      :: 校验打包产物确实包含最新代码
python test_harden.py          :: 防去除加固各项

```

> 自动化测试可用 `WM_CLOSE_CHOICE=minimize|quit|cancel` 环境变量直接指定关闭时的选择，
> 无需去点模态对话框。

## 标记与安全性说明

- 本工具用 `WB_WATERMARK_TEXT`（文本）/ `WB_WATERMARK_IMG`（图像）标记自己插入的水印：
  - **未开加固**时，标记直接写在图形的显示名（`wp:docPr/@name`）上；
  - **开了"多份冗余嵌入"**（伪装模式）时，显示名改成 `图片 101`、`Image 102` 这类普通插图名，
    私有标记改存到 `wp:docPr/@descr`（Word 中对应"替换文字/Alt Text"）。
    该属性是 OOXML 标准属性，实测 **Word 打开并另存后依然保留**，因此识别与一键清除不受影响。
- **清除**时会同时移除本工具标记的水印，以及任何"衬于文字下方"的图形（即 Word 原生水印），页眉与页脚都会扫描。
- 不会动正文、图片、表格等其它内容。

## 已知限制

- `.doc` 必须由装有 Word 的机器处理（格式限制，非本工具缺陷）。
- 目标文件正被 Word 打开时，插入/清除可能因文件锁失败；建议先关闭，或由守护在空闲时补回。
- 守护会周期性读写文件，文件很大或磁盘慢时请调大检查间隔。
- 字体完整列表依赖本机装有 Microsoft Word（Word 会给中文名，如"宋体/仿宋/微软雅黑"，约 1300 条）；
  仅 WPS 环境或 Word 不可用时会自动改用系统字体（数量约 480，但中文名较少）。读取时会临时启动一个
  不可见的 Word，**读完立即关闭**（见 [幽灵 Word](#另一个被误当成退出卡顿的问题幽灵-word)）。
- **水印无法做到"绝对删不掉"**。`.docx` 本质是 zip，任何拿到文件的人都能解压改 XML；一旦导出成图片，
  更是只剩像素。加固项的作用是抬高门槛，不是加密。详见 [防去除加固](#防去除加固能挡住什么挡不住什么)。
- 开了平铺后单页水印图形数量 = 行列数 ×（页眉份数 + 页脚份数）。份数过多时，Word 打开稍慢、文件略大
  （图片本身按内容去重，不会成倍增长）；默认 5×2 已能覆盖整页。
- 系统托盘常驻需要桌面环境支持托盘图标（Windows 默认支持）。
- 为了彻底消除关闭卡顿，运行体会常驻本机 `%LOCALAPPDATA%\WriteMark\runtime\<版本>\`（约 **135 MB**）。
  这是"换来秒退"的取舍：升级版本时旧目录会自动清理；想彻底卸载，删掉整个 `WriteMark` 目录即可。
- ~~退出时无论是点击关闭窗口还是直接结束 word.exe 的进程都会卡顿 30S 左右~~ **已于 v1.1.5 解决**：
  根因是微软 OfficePLUS（以及百度网盘、OneNote 便笺等）这类 COM 加载项 `LoadBehavior>=2` 随 Word 启动、
  关闭时做云端收尾；本程序内置的「Word 秒退」可一键禁用（或 [还原](#还原)）对应加载项。
  详见 [关闭 Word 卡十几秒](#关闭-word-卡十几秒不是本工具的锅)。
